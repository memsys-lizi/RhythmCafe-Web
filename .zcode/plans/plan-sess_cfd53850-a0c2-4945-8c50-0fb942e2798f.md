# 目标

新增给前端用的数据库搜索接口 `/api/levels/db`：**传入参数、返回结构与 `/api/levels` 完全一致**（前端 `api.ts` 解析逻辑零改动），数据源是官方 Datasette，**直接中转、不缓存全量数据**；前端不加新页面，只在现有分页器加"每页条数"下拉（20/50/100/200/500），最多 500 条/页。

# 核心架构（已全部实测验证）

**一次前端请求 = 一次官方请求**（顺序翻页时）。服务端只做三件事：参数翻译 → 官方请求 → 格式转换。

- 不缓存任何关卡数据。唯一状态是**游标映射**：官方 Datasette 忽略 `_offset`、只认 `_next` 游标（rowid keyset，实测 0→11→24 非线性，必须照抄），而前端传 `page`——服务端给每个查询指纹存一份"页号 → 游标值"列表（每项几十字节，TTL 5 分钟 + 条数上限 200 自动清理）。顺序翻页 1 次请求/页；直跳页码时服务端内部从已知页顺序补拉（客户端仍只看到 1 次响应）。

# 后端改动

## 1. `Server/src/upstream.ts` — 新增官方查询构建
- `buildDatasetteSearchUrl(params)` / `fetchUpstreamDatasetteSearch(params)`：固定指到 `rdlevels/rdlevels.json`，服务端拼接白名单参数（客户端不能传任意参数，保持项目安全风格）：
  - `_size`=per_page、`_next`=游标
  - `_where`：q 关键词 → 跨列 OR LIKE（song/song_alt/artist/description 等文本列 + tags/authors/artist_tokens 用带引号的 JSON 精配 `%"值"%`），带 LIKE 通配符转义（%/_/\）；tags_all/authors_all/artists_all 每个值一个 `__contains="值"`（AND 语义）
  - `difficulty__in=0,1,2,3`（CSV 单参数！实测重复参数会被 AND 拼错）
  - `min_bpm__gte` / `max_bpm__lte`
  - 审核：peer→`approval__gte=10`、pending→`approval__exact=0`、rejected→`approval__lt=0`、all→不加；缺省=peer；总加 `is_hidden__exact=0`（与官方搜索口径一致，实测无副作用）
  - `_sort=last_updated&_sort_by_desc=1`（与搜索 API 无 q 时排序一致）
  - `_facet=artist_tokens,tags,authors,difficulty,single_player,two_player`（submitter/club 是 JSON 整串，官方分桶无意义，不请求）

## 2. 新建 `Server/src/levelSearchDb.ts` — 查询翻译 + 游标映射 + 格式转换
- `searchLevelsDb(params)` 主函数返回与搜索 API 相同的 `props.results`：
  - hits：官方 rows（按 columns 顺序的数组）→ 用 columns 建索引 → Level 对象（tags/authors/artist_tokens/submitter/club 从 JSON 字符串解析为数组/对象，0/1 转 boolean，去掉 rowid）
  - `estimatedTotalHits` = filtered_table_rows_count、`limit` = per_page、`offset` = (page-1)*per_page、`query` = q、`processingTimeMs` = 请求耗时
  - `facetDistribution`：官方 facet_results 是**按 JSON 整串分桶**（实测），服务端拆桶后按数组元素累加还原单标签计数（数学等价，不需要全量数据）；highlighted = value
- 游标映射：模块级 Map（指纹 = 规范化查询串+排序+size），TTL 5 分钟惰性清理 + 上限 200 条

## 3. 新建 `Server/src/routes/levelsDb.ts` — 路由
`GET /api/levels/db`：
- 参数：q/page/tags_all/authors_all/artists_all/difficulty/min_bpm/max_bpm/peer_review 与 `/api/levels` 完全相同；新增 `per_page`（默认 20，>500 钳制为 500，<1 回退 20）；page <1 视为 1；未知参数忽略（项目风格）
- 返回外层 envelope 与 `/api/levels` 完全一致：`{action:'render', view:'cafe:level_search', overlay:false, metadata:{title:''}, props:{results:{...}}, context:{}, messages:[]}`
- 上游失败 → 502 UPSTREAM_UNAVAILABLE（与现有路由一致）

   - `per_page=500` → limit=500；`page=2` → offset=500 且行不重复（游标映射生效）
