# 目标（用户已确认的两个决策）

1. **返回格式**：Datasette 兼容透传 —— 参数（`_size`/`_next`/`_shape`）与响应结构和官方 `datasette.rhythm.cafe` 完全一致，只重写 `next_url` 指回镜像自己。你朋友的工具只需把 base URL 换成镜像的 `/api/db` 即可，解析逻辑零改动。
2. **改动范围**：只做后端 API，不动 Web 前端。

现有搜索 API 代理（`/api/levels`）保持锁死 22 条不变。

# 实测依据（已在官方上游验证）

- 官方 Datasette：`https://datasette.rhythm.cafe/rdlevels/rdlevels.json`
- `_size` 上限 1000（超限上游返回 400 `_size must be <= 1000`）
- **`_offset` 被上游静默忽略**（实测偏移 1000 仍返回第一页）——正确翻页用响应里的 `_next` 游标（`next_url` 形如 `http://datasette.rhythm.cafe/...&_next=2`，且是 http 不是 https，必须重写）
- 全库 7364 行；默认返回"位置数组行 + columns 字段"，`_shape=objects` 可拿命名对象
- 表中 tags/authors/artist_tokens/submitter/club 是 JSON 字符串（透传不转换）

# 改动文件（4 个，全部在 Server 侧）

## 1. `Server/src/upstream.ts` — 新增（沿用现有 env 默认值 + URL 构建 + fetch 封装模式）
- `DATASETTE_BASE_URL` 环境变量（默认 `https://datasette.rhythm.cafe`）
- `buildDatasetteUrl(query)`：固定路径 `/rdlevels/rdlevels.json`，只拼接 `_size`/`_next`/`_shape` 白名单参数（不透传 FTS 内部表、不透传任意 SQL）
- `fetchUpstreamDatasette(query)`：30s 超时、UPSTREAM_USER_AGENT、accept JSON

## 2. `Server/src/routes/datasette.ts` — 新建 `registerDatasetteRoutes`
注册 `GET /api/db/rdlevels/rdlevels.json`（路径镜像官方，保证"换 base URL 即用"）：
- 参数白名单 `_size`/`_next`/`_shape`，其余忽略（与现有 `buildLevelsUrl` 风格一致）
- **`_offset` 特判**：非 0 时返回 400 `{ error: 'OFFSET_NOT_SUPPORTED', message: '官方 Datasette 不支持 offset 分页，请使用 _next 游标' }`（上游静默忽略它，透传会造成静默错数据）
- 上游状态码 + content-type 透传（`_size=1001` 时上游 400 原样透传）
- 响应 JSON 里的 `next_url` 重写为镜像相对路径 `/api/db/rdlevels/rdlevels.json?_size=...&_next=...`
- 上游超时/失败 → 502 `UPSTREAM_UNAVAILABLE`（与现有路由一致）

## 3. `Server/src/server.ts` — 注册新路由（与 levels/downloads 并列）
生产 Nginx 与 dev Vite 代理都已覆盖 `/api` 前缀，无需改动。

## 4. `API.md` — 新增「数据库接口」章节
端点、参数表（`_size` ≤1000、`_next` 游标、`_shape`）、curl 全量拉取示例（循环 `_next` 直到无 `next_url`，约 8 次请求）、字段格式说明（默认位置数组 + `columns`；tags 等为 JSON 字符串）、`_offset` 拒绝原因。
